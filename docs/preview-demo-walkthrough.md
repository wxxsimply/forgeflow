# ForgeFlow：5 分钟模拟演示与讲解稿

更新：2026-09-18。用户已逐项确认现场演练结果；具体演练日期和页面显示版本未提供。

后续补充：用户已确认阶段 C 网页模拟流程与安全组成功，并逐项确认 HTTPS 登录、仓库选择、批准、拒绝状态、刷新恢复和注销保护。另有一个独立命令行真实案例完成了单次模型调用、人工审查、一次隔离测试和候选应用；它不是网页功能。演练反馈显示用户容易不清楚平台功能，因此讲解时需要反复明确这两条证据链的边界。

真实案例代码已通过 PR #75 合并为 `4403323`，四项 GitHub CI 全部成功。演示时可以展示该提交中的两个公开 demo 文件和脱敏审查记录，但不要打开仓库外任务目录、提供商控制台请求明细或任何凭据。

## 1. 先把项目讲准确

可以这样开场：

“ForgeFlow 是一个把软件任务放进受控流程的 Agent 项目。我关注的不只是模型能不能写代码，还包括它准备做什么、哪些操作要人批准、中途失败怎么恢复，以及事后能不能查清发生了什么。今天网页展示的是模拟规划和审批流程，不是让真实模型现场修改代码。”

这里的 Agent，可以理解为“围绕一个任务，按步骤调用模型和工具的软件”。模型负责给出建议，程序负责检查格式、限制权限、保存进度和决定是否继续。

当前公开预览保持 `planning + mock`，真实 Docker 执行关闭。Mock 的意思是程序提供固定结构的计划，不向外部模型发请求。计划里写着“实现”“测试”，只是计划内容，不代表这些动作已经执行。

网页进度图也列出了开发阶段节点；看到节点名称，不等于节点已经运行。要结合完成状态和事件记录判断。

## 2. 演示前准备（不算进 5 分钟）

- 阶段 C 的登录、仓库选择、模拟流程、注销和安全组已经用户人工确认；正式演示前仍应检查当前服务是否可用，不把历史验收当成现场状态。
- 打开 `https://39.102.136.31/login`，确认无证书警告。用自己的管理员或操作员账号，不把账号密码交给面试官，不展示 Cookie、密钥或私有环境文件。
- 登记仓库：名称 `demo`，服务端仓库绝对路径 `/repositories/demo`，默认基线 `main`。如果同一路径已登记，直接选用，不反复创建。
- 仓库路径是应用容器里的路径，不填写 Windows 的 `D:\Code\forgeflow`，也不填写服务器宿主机路径。
- 新任务的基线版本填 `main`，最大迭代次数填 `1`。网页预算卡是配置提示，不是付款授权，也不能靠卡片文字证明费用硬上限；本演示不启用真实模型。
- 准备两个独立模拟任务：一个走批准，一个走拒绝。不要在同一个已拒绝任务上寻找“再批准”的入口。
- 正式演示前先排练；网络不稳定时可展示自己真实录制并脱敏的截图或录像，注明录制日期，不伪装成现场成功。

## 3. 五分钟按这个顺序讲

### 0:00～0:40：定位

用第 1 节的开场白。强调“今天展示流程控制”，不说“已经自动解决所有编程问题”。

### 0:40～1:30：创建任务

选择演示仓库，填写：

> 演示 A：请为 greeting.go 的空名字处理提出一个最小修改计划，说明风险和建议测试。只演示规划与审批，不执行真实修改。

点击“创建并查看任务”。说明：“仓库和任务有明确范围，任务创建后会有自己的编号，后续审批和记录都能关联回它。”

输入框以 UTF-8 字节计数。用一句话解释：“一个常见汉字通常占三个字节，所以前后端统一按字节限制，避免页面说能提交，服务器却拒绝。”不要现场粘贴几千字拖延演示。

### 1:30～2:30：计划与人工审批

等任务出现待审批提示，点击“检查审批”，看计划摘要、风险、影响范围。备注写“仅批准本次模拟计划”，点击“批准并继续”，在确认弹窗中确认。

预期：模拟规划任务进入 `completed`。讲清楚：“这里的完成，是规划流程完成，不是修改源码或运行测试完成。Mock 没有真正分析源码，可能影响的文件为空也不代表没有风险。”

如果状态没有变化，查看事件或刷新当前任务，不反复创建新任务，不把失败当成功讲过去。

### 2:30～3:30：拒绝审批案例

为同一演示仓库创建另一个模拟任务：

> 演示 B：请为 greeting.go 的空名字处理提出计划。本任务用于演示人工拒绝；不授权实际改动。

注意：文字“不授权”不是技术上的审批决定，真正的决定要点击按钮。

进入“检查审批”，备注写“演示拒绝：需求尚未确认”，点击“拒绝”，再确认弹窗。预期任务变为 `cancelled`（已取消），审批变为 `rejected`（已拒绝）。可以从审批列表“已拒绝”查看决定。

讲解：“任务停止在人工决定这里，审批不是装饰按钮。但这个 Mock 案例没有真实工具执行，所以它只证明拒绝后的流程分支，不能单靠它证明生产沙箱绝对安全。”

### 3:30～4:20：记录与恢复

展示任务编号、版本和事件时间线，再刷新当前页面。讲解：“网页不是进度的唯一保存位置。程序保存了任务状态，刷新后查询同一任务，而不是从头创建。”

刷新页面只能展示页面重新读取记录，不等于模拟了后端崩溃。本轮另有本地测试用新的 Service 和存储实例读取旧检查点，验证在审批处可以继续；它仍不是线上故障演练。

### 4:20～5:00：总结与边界

“我这次展示了任务范围、人工审批、拒绝分支和可查看的记录。项目另有一个独立命令行真实案例：在明确的数据和费用授权下只调用一次模型，人工看过 Diff 后再单独批准隔离测试，测试通过才把精确候选写入公开 demo。这个案例不等于网页已经支持真实执行；大规模评测与生产发布仍是另外的验收。”

最后注销。不要把管理员会话留在共享电脑或公开演示设备上。

## 4. 面试官追问时这样回答

### 这不就是套了一个聊天接口吗？

“模型调用只是其中一步。我做的工程部分是把步骤、审批、权限、记录和恢复串起来。目前网页演示用 Mock，是为了验证流程，不是展示模型效果。真实调用效果需要另外拿案例证明。”

### 为什么不让 Agent 全自动做？

“生成计划和执行危险操作不是一回事。批准前让人看范围与风险，程序还要检查权限和执行约束。人工批准不能替代程序校验，程序校验也不能替人判断业务是否应该做。”

### 网络断了，再点一次会不会创建两份任务？

“前端对同一份输入重试会保留请求标识；后端把创建任务和保存去重记录放在同一个数据库事务里，一起成功或一起失败。相同标识不能偷偷换成另一份内容。”

补充边界：“换新页面或改输入可能生成新标识，因此不能承诺内容一样就永远只创建一次。旧 pending 记录也不能乱删，要核对它是否已经对应真实任务。”

代码入口：[新建任务页面](../web/src/pages/NewRunPage.tsx)、[事务去重](../internal/checkpoint/idempotency.go)。本轮没有重跑数据库去重集成测试；此前 PR #52 的测试是历史证据。

### 能保证任何操作都恰好执行一次吗？

“不能这样笼统保证。内部任务创建可以通过事务和请求标识去重，但外部命令可能已经执行、回执却没保存。要按工具区分能否安全重试，对结果不确定的操作先核对，不能无脑重放。”

### 恢复时计划已经被人改了怎么办？

“恢复不是继续执行任何新内容。本轮测试覆盖审批依据变化后拒绝恢复；审批要和具体状态关联。网页遇到版本冲突也会重新加载，要求基于最新版本再检查。”

### 你怎么证明没有真实修改代码？

“当前规划工作流的定义里没有实际开发执行节点，Mock 也只返回计划；我不会拿计划文本当作 Diff。如果要声称某次真实任务保留了原仓库，还应拿基线、工作区差异和工具记录逐项核对。”

代码入口：[Mock 计划](../internal/planner/mock.go)、[规划工作流](../internal/graph/planning.go)、[审批页面](../web/src/pages/ApprovalDetailPage.tsx)。

### 独立真实案例证据

2026-09-17，仓库所有者授权 `deepseek-flash` 只接收公开 demo 的任务描述和四个白名单文件，最多 128 KiB、恰好一次调用、禁止重试，人民币上限 3 元。实际调用使用 1,254 个输入 token 和 464 个输出 token，本地费用估算约为人民币 0.00622 元。用户随后人工核对 DeepSeek，确认实际扣费低于人民币 0.01 元，且只有 1 次对应调用；具体账单核对日期未提供。该结果首次回报于 2026-09-17，并于 2026-09-18 再次确认。

候选只修改 `greeting.go` 与 `greeting_test.go`：姓名先去除首尾空白，空值返回 `Hello, guest!`，并补充普通姓名、中文姓名、首尾空白和空字符串测试。人工静态审查后，仓库所有者针对精确候选快照另行批准一次无网络隔离测试；测试退出码为 0、未 OOM、没有重试。之后又单独批准把同一快照应用到公开 demo，当前四文件快照哈希与已测试候选一致。

讲解时应强调：这是独立 CLI 案例，不是网页现场调用；原始响应和任务数据库不公开；本地估算与供应商侧人工核对结果是两类证据；服务器没有部署本次改动，批量 Eval 也没有重跑。

该案例已随 PR #75 通过 Go、Web、PostgreSQL 和部署资产四项 GitHub 检查。Linux `validate` 覆盖了完整脚本集合；这可以作为合并质量证据，但不能代替候选自己的隔离测试收据，也不能证明线上网页已启用真实模型。
