## 3. 仓库所有者需要接受的发布约束

- 分发二进制、容器镜像或前端产物时，保留适用的版权、许可证和 NOTICE 信息。
- 不删除第三方源码文件中已有的许可证头。
- 如果以后复制或修改 MPL-2.0 覆盖的源码文件，必须单独复核其文件级源码提供义务。
- 不把 `web/node_modules`、Go module cache 或测试工具目录直接打包为产品交付物。
- 升级或新增依赖时重新生成许可证清单，并在 Release 审查中检查许可证变化。
- 正式公开或商业发布前生成随发布物交付的第三方 Notices；许可证原文应来自对应依赖版本，不以本摘要代替。
