# 离线请求流程：先批准、先记账，再保存返回提案

这是阶段 D 的准备工具，不是 DeepSeek 客户端。它没有 HTTP 请求、密钥读取、真实模型选择或自动重试功能。唯一的 `run-fake` 入口调用本地固定函数，在原 Go 文件末尾加一行说明注释，实际费用为零，也不会执行返回代码。

## 1. 这轮接通了什么

同一个任务的 `task.sqlite` 现在可以保存请求正文、批准摘要、预算预留、返回提案及后续审批收据。

1. 从归档任务正文和四文件快照生成确定的请求内容，默认只显示摘要。
2. 操作者明确批准这个请求摘要后，在一个事务中保存请求及预算预留。
3. 事务提交成功才调用固定 Fake 函数，一次，不自动重试。
4. 校验返回提案后，在一个事务中保存返回字节、提案、初始测试收据和预算结算。
5. 测试候选代码仍要另行查看 Diff 并批准；批准请求不等于批准执行代码。

“事务”就是这些记录一起成功或一起失败，避免只保存提案、却漏记费用或审批状态。它不能撤销已经发生的外部请求，因此中断时必须保守阻断。

## 2. 怎么操作

先按 [任务归档说明](preview-demo-task-archive.md) 准备一个独立离线任务。所有尖括号都是占位符；使用自定义私有根目录时，每条命令都要传相同的 `--root`。不要把已有真实任务、旧预算或未知结果删掉后重建。

默认只看请求摘要，不执行 Fake、不读取外部源码：

```powershell
python -B scripts/preview_demo_request.py preview --task-id "<32位任务编号>" --reserve-nano-usd 1000
```

输出的 `requestPreview` 包含任务编号、源快照及请求 SHA-256、策略摘要、固定 Fake 模型、预留金额及 `authorizationSha256`。批准摘要同时绑定请求精确字节、协议版本、预算策略和本次预留；换内容或换预留金额后，旧批准无效。

确实需要审查请求原文时才添加 `--show-payload`。这会打印归档任务和四文件源码，必须在私有终端查看，不上传截图/PR/公共日志。请求最多 1 MiB（包括 JSON 转义和固定协议文字），原源码仍最多 128 KiB，任务正文仍最多 20,000 字节。不包含旧提案、测试日志、数据库路径、凭据或其他文件；白名单不是秘密扫描器，仍需人工检查任务与四文件本身。

确认要做一次**离线模拟**后：

```powershell
python -B scripts/preview_demo_request.py run-fake --task-id "<同一任务编号>" --reserve-nano-usd 1000 --approve-request-sha256 "<刚审查的authorizationSha256>"
python -B scripts/preview_demo_request.py inspect --task-id "<同一任务编号>"
python -B scripts/preview_demo_task.py review --task-id "<同一任务编号>"
```

默认预留 `1000 nano-USD` 只是 Fake 记账单位，不是人民币报价，也不是用户付费授权。成功模拟会占一次预算调用计数，结算为零；`modelCalls:0` 是本次实际模型调用次数，而 `budget.attempts` 包含离线模拟记账。

结果的来源为 `fake_request`，明确不同于 `propose` 人工导入的 `manual_import`。返回内容只有注释变化，不解决实际需求，不能当作模型改代码案例。

`review` 只展示 Diff。若后续决定测试，必须使用它给出的 **`approvalSha256`**，走原有 `preview_demo_task.py test`。不要把请求的 **`authorizationSha256`** 填过去；两次批准覆盖不同动作。本轮开发验证没有运行真实 Docker 候选测试。

## 3. 状态和失败处理

- `request:null`：该任务尚未保存请求。`preview` 不新建请求。
- `reserved`：批准、请求和预算已保存，可能正在调用，也可能进程中断；不能自动再请求。
- `completed`：有效 Fake 返回、提案、初始测试收据和零费用结算一起保存。只代表模拟请求完成，不代表测试通过或需求满足。
- `unknown`：调用、响应校验或保存过程发生异常。保留次数和最高费用预留，不自动退款或重试。

如果开始事务没有提交，既不调用 Fake，也不留下半份请求或额度扣减。返回结果保存失败则回滚返回提案、收据和结算，尽量标记 `unknown`；连失败状态都写不进去时保留原来的 `reserved`，仍阻断。进程强退同样保留已提交记录。

每个任务只允许一次请求流程，即使底层预算策略允许三次，也不能重跑 `run-fake`。先人工导入提案的任务不能再请求；请求开始后也不能人工导入替换其结果。并发请求与人工导入在同一数据库事务中互斥，不接受额外账本或收据路径。

没有重试、恢复、强制通过或修改真实用量的 CLI。错误先保留私有数据库及 journal，核对原因，不删库、复制旧库、另建根目录或直接调用底层组件来续跑。底层人工结算接口不等于这个任务流程已实现人工恢复；更改关联记录会阻断，不会自动补齐。

## 4. 还没完成的部分

- DeepSeek 的真实 HTTP 请求、认证和原始回执解析；不能把固定 Fake 函数换成真实网络调用，就声称已经满足本说明的限次、限费保证。
- 最新价格、token 上限、人民币换算和可靠的请求前最高费用计算。
- 本轮真实数据发送范围、模型、次数和费用的人工确认；Fake 摘要不是付费授权，也不是身份签名。
- 真实候选的 Docker 集成验证、需求验收和网页完整流程。
- 防篡改审计或跨目录全局防重放。哈希检查会发现部分内容混用，但无法阻止有写权限的人整体回滚同路径数据库。

当前只保存合法 Fake 返回的精确提案字节，不收集异常中的原始响应或日志，也不宣称已有完整真实提供商证据链。任务数据库新增请求原文，依旧必须放在私有受控且 Git 忽略的目录。
