# DeepSeek 离线协议与费用检查

本轮只完成“准备请求格式、检查返回内容、计算费用估算”的 Python 模块：[preview_demo_deepseek.py](../scripts/preview_demo_deepseek.py)。没有 HTTP 客户端、密钥读取、付费 CLI、授权保存或真实费用结算。不能直接把它替换到 Fake 回调里就开始付费。

## 1. 为什么需要单独做这一层

模型可能返回截断 JSON、其他任务的内容、工具调用或缺失的用量。调用可能已经收费，因此“提案不能用”和“费用不知道”必须分开处理。同时，之前的 Fake 预算和批准只针对离线模拟，不能直接升级成真实请求授权。

本轮只读取已有归档输入，不改变它的 `provider=fake`、预算或收据。即使预算估算够用，结果也始终显示 `paidExecutionEnabled:false` 和 `readyForPaidExecution:false`。

## 2. 官方资料核对

核对日期：2026-09-15。模型名称、参数和价格会变化，真正调用前需要再次核对。

- 当前官方列出 `deepseek-flash` 与 `deepseek-v4-pro`；模块明确列出这两个名称，不静默回退到旧别名。[模型与价格](https://api-docs.deepseek.com/quick_start/pricing/)
- 请求使用 `/chat/completions`，显式设置非流式、关闭思考、限制输出，并要求 JSON 返回。收到截断结果或工具调用时，不将其作为可执行提案。[Chat Completions API](https://api-docs.deepseek.com/zh-cn/api/create-chat-completion/)
- 官方存在峰谷和缓存价格区别，且可能调整价格；本轮不内置可直接启用的价格表，不自动使用低谷折扣。[模型与价格](https://api-docs.deepseek.com/quick_start/pricing/)

模型白名单不等于长期可用保证。模块中 `8192` 是本项目的输出上限，不是官方最大输出限制。

## 3. 请求准备

`prepare()` 从归档提取任务正文、四文件精确内容、任务编号和摘要，生成固定的 system/user 两条消息。不会加入旧提案、旧审批、原始 Evidence、任务数据库路径、其他文件或凭据。请求正文最多 2 MiB，原有任务 20,000 字节和源码 128 KiB 限制保持不变。

返回的对象保存不可变字节；默认摘要及对象展示不打印源码。摘要绑定正文、模型、价格配置、汇率假设、输出上限、超时和预算换算结果。字段叫 `planSha256`，它只是内容指纹，**不是人工批准，更不是付费授权**。

接口供后续接线使用，本轮没有给用户新增一个可发送请求的命令。

## 4. 价格和人民币上限

`PricingSnapshot` 必须显式提供模型、三种价格、汇率假设及有效期，不提供默认真实报价：

- 价格单位为“每百万 token 的 nano-USD”，`1 USD = 1,000,000,000 nano-USD`。
- 人民币预算使用整数“分”，汇率使用整数“百万分之一人民币/美元”。禁止浮点数、布尔值、负数和零价格。
- 汇率必须是操作者核对的保守上界。工具不获取实时汇率，不保证账户实际兑换方式、税费或充值手续费与它一致。
- 价格有效窗口最多 24 小时，而且必须覆盖请求的整个计划超时。过期、尚未生效、窗口不足时阻断。
- 人民币换成允许花费的美元额度时向下取整；按用量计算费用估算时向上取整。

请求前按当前文档 1M 上下文的保守计数上限 `1,048,576` 加指定输出上限，使用全部未缓存输入价预估。不拿字符数或源码字节数冒充可靠 token 上限，不假设缓存一定命中。这样的估算可能明显偏高：小预算显示 `fitsBudget:false` 是正常的，不应自动扩大预算或偷偷降低预留。

这仍是基于已核对模型限制、人工提供价格和汇率的保守估算，不是硬性收费保证。模型限制或价格变化需要重核；未来真实传输层还必须在预算不足时拒绝发送。URL 与指纹只能检查配置一致性，不能证明提供的价格/汇率是真实的。

测试中的价格与汇率是合成数据，不应复制作为真实报价。

## 5. 返回内容和费用分开判断

`parse_response()` 只解析调用者提供的内存字节，不联网、不运行工具、不自动重试。原始返回最多 2 MiB；未来 HTTP 层仍须在读取过程中限制字节量，不能无限读完才调用本函数。

- HTTP 非 200、身份/模型不符、缺少用量或用量不一致：返回固定错误，费用保持未知，不能算零费用或自动重试。
- 输入总量必须等于缓存命中加未命中量，总量必须等于输入加输出；可选的细分字段也必须一致。拒绝负数、浮点数及布尔值伪装的计数。
- 用量可核对，但结果截断、非 JSON、任务摘要不匹配、修改了白名单外文件、包含工具调用或意外思考内容：保留 `estimatedNanoUsd`，但 `proposalAccepted:false`。
- 用量超过请求上限或估算超过预留/预算：保留该估算并标记 `limitExceeded:true`，不返回可执行提案。不能掩盖已经发生的超额。
- 合法提案复用原有两文件白名单及任务/原始快照绑定检查，后续仍要人工审查和单独批准测试。

费用字段刻意命名为“估算”：按人工输入的峰值价格计算，不等于真实账单。解析结果在内存中保留原始响应与合法提案字节，普通摘要不输出这些内容；当前尚未实现与真实请求账本的持久化关联。不要把 `.raw` 当作可公开日志。
