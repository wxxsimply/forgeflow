# 单次 HTTPS 传输：内部组件与使用边界

本轮新增 [传输模块](../scripts/preview_demo_https.py)。内部 `send_once()` 已具备真实联网能力，但**没有接到任务命令行或网页，没有执行真实请求**。目前不应手动调用它或内部子进程入口；真实授权、预算预留和回执保存尚未接通。

## 1. 做了哪些限制

- 地址固定为 `api.deepseek.com:443` 的 `/chat/completions`，调用者不能传其他 URL 或代理。
- 使用系统信任根及 TLS 证书/主机名校验，不提供关闭验证的参数。不固定证书指纹，也不绕过证书错误。
- 一次调用只执行一个 POST，不跟随 301/302/307/308，不自动重试 429、500、连接失败或读取超时。
- 发送前重验价格有效期、预算是否够用、请求与捕获快照是否一致；子进程再次校验请求格式和四文件白名单，不允许工具、思考模式或任意消息列表。
- 仅接收未压缩的 JSON 响应；提前检查声明长度，读取最多 2 MiB 加一个探测字节。过大、空响应或长度不符时失败，避免无界读取或解压。
- 原始 HTTP 返回只在内存和私有管道中传递，结果对象的普通展示不包含正文。HTTP 错误不打印响应内容、请求头、密钥或原始异常。

这里的固定请求与 TLS 使用 Python 标准库；真实模型响应仍需交给前一轮的协议解析器检查用量和提案，HTTP 200 不等于任务成功。[Python HTTPSConnection 文档](https://docs.python.org/3/library/http.client.html#http.client.HTTPSConnection)

## 2. 为什么用独立子进程

单个 socket 的超时不等于整个请求的总超时，DNS 或分段读取也可能拖延。本实现把固定网络操作放进专用子进程，由父进程按单调时钟监督：

1. 父进程先检查输入，再启动唯一的子进程。
2. DNS、连接、TLS、POST 和响应读取都在子进程里进行。
3. 超时或用户中断时，父进程只终止自己启动的这个子进程，并核对退出，不杀进程树或其他服务。
4. 清理另有最多 2 秒的等待；无法确认退出时报告 `https_cleanup_unconfirmed`，错误对象携带本次 `worker_pid`，由后续调度器提供人工核查信息，不能自动重试。

普通通信预算为计划中的 1～120 秒。OS 创建进程本身不一定可立即中断，所以不能宣称任何系统故障下都严格在该秒数内返回；它不包含最多 2 秒的清理等待。进程创建完成后若预算已耗尽，不再传入请求正文，立即终止。[Python subprocess 超时与清理说明](https://docs.python.org/3/library/subprocess.html#subprocess.Popen.communicate)

终止本地子进程不能撤销远端已经收到的请求。超时、断线、证书错误或 HTTP 失败都不能自动记为“免费”；未来账本必须保留预留或未知状态。

## 3. 密钥如何传递

模块不读取密钥文件、环境变量中的 API Key 或聊天记录。未来可信调度器需要显式传入密钥；父进程只通过 stdin 管道传给子进程，不放进命令行、环境或临时文件。

子进程使用 Python 隔离模式，忽略用户 `PYTHONPATH`；仅允许本项目受信任的相邻模块，环境只保留少量系统/临时目录信息。Windows 启动时隐藏窗口，stderr 不收集，stdout 仅作内部受限响应管道。系统代理和其他业务环境变量不传入。

这不是加密保险箱：拥有本机足够权限的人仍可能查看进程内存。本子进程也不是执行模型生成代码的沙箱，它只运行受信任的固定传输代码；原有候选代码沙箱仍是独立的另一层。

## 4. 为什么现在仍不能付费运行

后续进度：下列授权、预算和回执保存已由 [内部真实任务模块](preview-demo-real-task-ledger.md) 接通并离线验证，但没有用户付费 CLI 或真实调用验收。下面的剩余项描述本 HTTPS 组件完成时的历史边界。

`send_once()` 是低层组件，不验证用户身份、不保存批准、不预留费用、不结算，也不把回执落盘。调用它之前，未来调度器必须已经持久保存本轮真实批准和最高费用预留。输入复核及 `fitsBudget` 不是付费授权。

目前的 Fake 请求入口没有引用或调用它；`PreparedRequest` 继续显示付费未就绪。没有面向用户的付费命令，内部 `--internal-worker` 只用于父子进程通信，不应手动运行、复制真实密钥进去或用它绕过账本。

还需要完成：

- 单独的真实任务策略、数据范围、次数、费用与价格/汇率确认，不能直接修改旧 Fake 账本。
- 真实批准、预算和本组件的调用前持久化绑定；所有失败保守阻断。
- 原始回执私有保存、用量未知与提案无效的不同处理、结果持久化及费用核对。
- 独立测试批准、真实候选测试及业务需求验收；网页仍为 Mock。
