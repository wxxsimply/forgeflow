# 真实任务的批准、预算与回执保存

记录日期：2026-09-15。基线：PR #65，`763e7d6ff3e42ba5048bd65680466289f1c15d14`。

本轮新增 `scripts/preview_demo_real_task.py`，只接通内部流程，不是已经可以直接使用的网页功能或付费命令。未发送真实请求，也未执行模型生成的代码。

## 已实现的流程

1. 创建独立真实任务，保存任务正文、四文件公开演示快照、模型、人工价格/汇率、人民币额度和请求参数。旧 Fake 任务不能转换或复用。
2. 内部 `approve()` 保存操作者确认参考文本，批准绑定具体计划摘要，不能替换；摘要包括精确请求内容、模型、价格指纹、预留额度和超时。
3. 内部 `execute()` 检查批准、价格有效期和预算；在同一事务保存请求开始及费用预留，提交成功后才调用单次 HTTPS。
4. 有效 HTTP 200 响应原文、费用估算、状态及合法提案的初始测试收据一起保存；候选测试仍需另外批准。

每个任务最多一次请求，不自动重试。计划变化、并发、进程突然退出和保存失败都不能通过重启绕过。首次初始化失败会留下占用目录，不自动覆盖。

## 状态如何理解

| 状态 | 含义与后续行为 |
| --- | --- |
| `prepared` | 已准备，未批准；不发送、不预留 |
| `approved` | 批准已保存，发出前仍核对价格有效期 |
| `running` | 已提交请求开始和最高费用预留，禁止重发 |
| `unknown` | 传输或保存失败；保留全部预留，不能认为没有扣费 |
| `usage_unknown` | 响应无法可靠解析用量；保存原文、保留预留，不生成候选 |
| `rejected` | 用量可核对但提案无效或超限；保存估算与原文，不执行、不重试 |
| `completed` | 合法提案和请求回执已保存，不代表候选测试通过 |

请求结果保存失败时，响应、收据和结算一起回滚，尽力标记未知；如果连未知状态也无法保存，原有 `running` 和预留仍阻止重发。传输层拒绝的响应或连接错误不一定有正文可保存。当前没有解除未知状态的 CLI，不能删库或另建任务规避阻断，应先核对提供商记录。

## 费用、批准与隐私边界

- 金额使用整数，按人工核对价格与返回用量保守估算，标记 `conservative_estimate_not_invoice`；不是实际账单或提供商硬性收费保证。
- 价格和模型限制在真正使用前仍须重新核对。测试价格与汇率是合成数据，不可用作收费配置。
- 原始任务、快照、批准参考文本和响应仅保存在调用者提供的受控私有目录。该目录不得加入 Git、公开下载或挂载给候选沙箱；Windows 目录权限仍须单独配置。
- 普通摘要只输出状态、指纹、用量和估算，不输出原文或批准参考文本。模块不读取密钥文件、不保存传入的 API Key。
- 本地批准记录不是身份鉴权或数字签名。组件依赖可信本机操作者，不可直接作为匿名网页接口。目录绑定和同库事务不提供防篡改账务或跨目录全局防重放。
