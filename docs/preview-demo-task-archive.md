# 离线任务归档：输入、提案和审批记录放在一起

这个工具为阶段 D 做准备，不调用模型、不读取 API Key、不修改线上网站。默认准备、导入、核对和审查都不运行代码；只有显式使用 `test` 并提供批准摘要，才运行固定的无网络 Docker 测试。它不是已经完成的真实模型案例。

## 1. 保存什么

每个任务对应 `<私有根目录>/<任务编号>/task.sqlite`，里面包含：

- 用户给定的任务正文原始字节，非空 UTF-8，最多 20,000 字节。
- 公开 demo 的 `README.md`、`go.mod`、`greeting.go`、`greeting_test.go` 原始字节，合计最多 128 KiB。
- 与这些字节摘要绑定的预算策略和预算记录。此入口固定为 Fake Provider，不是 DeepSeek 的真实价格或授权。
- 任务编号及绑定目录位置，用来发现误移动、误复制和输入混用。
- 首次人工导入的提案 JSON 精确字节及 SHA-256（最多 1 MiB），和同一事务创建的审批收据。
- 批准后的执行状态、实际镜像 ID、退出码、OOM 标志和时间；不存测试原始日志。
- 选择新的 [离线 Fake 请求入口](preview-demo-request-lifecycle.md) 时，还会保存请求精确字节、请求批准、关联预算预留及合法 Fake 返回；这与人工导入提案二选一，不是真实模型调用。

原始文件后续修改不会替换已归档快照。数据库文件包含源码和任务正文，必须留在私有受控位置，不能提交 Git、上传 PR 或作为公开演示附件。摘要检查不是秘密扫描，不能把密码或私有评分源码混进模板。

## 2. 显式准备任务

在项目根目录操作。先人工创建私有根目录；默认是 `.forgeflow/demo-tasks`，已被仓库忽略。工具不自动创建父目录，也不替你配置 ACL。Windows 请确认只有受信任账户可访问；POSIX 新任务目录为 `0700`，数据库为 `0600`。

准备一份自己审阅过的 UTF-8 任务文本，指定新的 32 位小写十六进制任务编号。以下都是模板，尖括号需要替换：

```powershell
python -B scripts/preview_demo_task.py prepare --task-id "<32位任务编号>" --task-file "<受控任务文本文件>"
```

默认读取公开 `examples/preview-demo`。`--source` 只接受平铺四文件目录，禁止 `.git`、额外文件、链接等；不得把私有根目录放进源码目录。`--root` 可指定另一个已存在的受控目录，但不要用更换根目录来重新开始同一任务。

Fake 预算默认最多 1 次、1,000,000 nano-USD 记账额度，可以显式指定 `--max-calls 1..3` 和 `--max-cost-nano-usd <正整数>`。这些只是离线账务参数，不是人民币报价，不授权任何真实费用；工具本身没有调用模型的命令。

`prepare` 成功仅表示输入和初始账本有效。不要将 `checksPassed:true` 解读为模型任务完成、测试通过或可开始付费。

## 3. 之后只核对已有归档

```powershell
python -B scripts/preview_demo_task.py inspect --task-id "<同一任务编号>"
```

使用自定义根目录时，所有命令都要传相同 `--root`。核对无需再读取原始任务文件，输出只含任务/文件摘要、字节数、预算及提案收据状态，不含正文、源码、Diff 或目录位置。尚未导入时 `proposal:null`，旧归档仍可核对。`modelCalls:0` 表示这次命令没有调用模型；历史 Fake 记账次数看 `budget.attempts`。

工具不提供覆盖、清空、重置或自动补齐失败归档的命令：

- 同一根目录、同一任务编号只允许首次创建；并发创建也只能一个成功。
- 创建中断会保留已占用目录。数据库或归档表缺失时停止，不能删除目录后重建来掩盖失败。
- 已预留但未结清的预算重启后仍保留，阻止后续 Fake 调用；不会将未知用量当作免费。
- 复制或移动到另一位置、改变任务编号或源内容，会在加载时拒绝；只改 Provider 成真实模型也会被拒绝。

遇到错误先保留目录并核对原因，不删除数据库、journal 或原始输入。数据库不是防篡改审计系统，摘要不能阻止有写权限的人同时篡改数据与策略，也无法识别恢复到同一路径的完整旧备份。当前唯一性只限受控根目录，不能声称全局防重放。

## 4. 导入提案，审查后再决定是否测试

提案格式沿用 [补丁说明](preview-demo-patch-review.md)：任务编号、任务正文摘要和原始快照摘要必须与归档相符，只能替换 `greeting.go`、`greeting_test.go`。导入前仍检查 UTF-8、禁止额外字段/路径及候选 128 KiB 上限。`propose` 的人工导入标记为 `manual_import`；新离线请求入口的固定模拟返回标记为 `fake_request`。两者都不能说成 DeepSeek 生成，后者还必须有匹配的请求和预算来源记录。

```powershell
python -B scripts/preview_demo_task.py propose --task-id "<同一任务编号>" --proposal "<受控提案JSON文件>"
python -B scripts/preview_demo_task.py review --task-id "<同一任务编号>"
```

`propose` 把提案和初始收据一起提交：要么都有，要么都没有。重复导入拒绝，即便只是 JSON 空格不同；不覆盖或重置已使用收据。已知事务回滚且两张表都不存在时可重新导入；如果只有一张表，直接阻断，不自动修复。初始 `reviewed` 只是经过格式和摘要检查、等待批准，不是人工已经读过或同意执行。

`review` 明确输出 `review.diff` 和 `review.approvalSha256`，请在私有终端审阅，不上传原始输出。之后即使外部提案文件或源码改变/删除，也只使用归档中的字节。原始归档、提案或收据校验不符时停止。

只有确认改动和测试内容合理、已准备可信的本地缓存镜像，才执行：

```powershell
python -B scripts/preview_demo_task.py test --task-id "<同一任务编号>" --approve-sha256 "<刚审查的approvalSha256>" --image golang:1.22 --timeout 90
python -B scripts/preview_demo_task.py inspect --task-id "<同一任务编号>"
```

这里的 `test` 会实际执行候选代码，不属于默认核对。它不接受另传源目录、提案文件或收据数据库。固定沙箱仍为无网络、非 root、只读源码和根文件系统、限内存/CPU/PID 的 Go 测试，默认总超时 90 秒、最多 120 秒，不自动拉镜像，不覆盖原始仓库。

- 正确的批准先保存为 `running`，成功提交后才启动沙箱；错误批准不会消耗收据。
- 正常结束保存为 `completed`，包括测试失败的结果。`completed` 不等于通过，更不等于满足需求。
- 异常保存为 `unknown`；进程强退或结果写入失败可能留在 `running`。这些状态和 `completed` 都不能自动再执行。
- `sandboxAttempted` 表示已进入沙箱调用，`sandboxExecuted` 表示沙箱完整返回（包括清理完成），不能单独证明测试成功；若保存失败，命令仍返回失败。清理无法确认时输出本次容器名，保留记录人工检查。
- 普通 `inspect` 成功只表示归档有效；历史测试结果看 `proposal.evidence.result.passed`。`test` 自身失败返回非零退出码。

## 5. 边界与快速验证

本文件的 `prepare/inspect/propose/review/test` 不会发送模型请求或新增、结算模型调用次数。本地审查/测试不消耗 Fake 请求额度，待核对预算仍保留。另一个 [离线请求入口](preview-demo-request-lifecycle.md) 已接通 Fake 批准、预算及返回提案保存，会占一次 Fake 预算计数；每个任务只能选择人工导入或请求流程，不能在请求开始后手动替换提案。真实 HTTP、人民币费用上限、付费授权、真实响应来源和原始回执仍待实现。

独立补丁 CLI 保留兼容，但不能另建收据作为本任务的“重试”。同库一次性检查不是身份签名，也不能阻止有写权限的人整体回滚数据库；请勿复制或删库续跑。模型或人工都可能改测试制造“通过”，必须人工检查语义。此入口不提供导出到任意目录、应用到原始仓库、付费调用或网页闭环。

快速验证：

```powershell
python -B -m unittest discover -s scripts -p 'test_preview_demo_*.py' -q
```
