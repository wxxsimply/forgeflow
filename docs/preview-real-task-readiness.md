## 3. 现有入口核查结果

- [CLI](../cmd/forgeflow/main.go) 的 `plan`/`approve` 使用规划 Service，不能仅靠切换模型就得到完整开发执行。
- `eval execute` 只接受 `software/v1`，要求 Fixture 与 Grader 仓库。`--limit` 限制新增案例数，不等于 HTTP 请求次数上限，不能把它写成“最多调用三次”。
- [Eval 费用控制](../internal/evalexec/budget.go) 已有调用前预留及累计费用机制，但使用美元，且没有自动接入独立 demo 命令。人民币上限、价格有效期、重试计数和未知费用处理仍须为新入口核对。
- [Grader 执行](../internal/evalexec/grader.go) 使用宿主机 `go run`；Git worktree 本身不是进程隔离，不能因为用了 worktree 就宣称生成代码完全隔离。
- [开发流程测试](../internal/application/development_test.go) 使用固定 Fake 补丁及测试 Runner，不能当作已经接通真实模型的命令行入口。

结论：不直接复制旧的付费 Eval 命令，也不在公网部署中开启 Docker 执行。先补齐专用入口，并用 Fake Provider 验证预算、越界、异常和停止路径，才进入真实调用。

## 4. 本轮免费隔离基线检查

本机 Docker Engine 可连接，版本为 `28.4.0`。使用已缓存的 `golang:1.22-alpine`，运行前解析本地不可变 image ID，`--pull never`，没有下载镜像。只将 `examples/preview-demo` 只读挂载至 `/workspace`。

隔离条件：无网络、用户 `10001:10001`、只读根文件系统、去掉所有 Linux capabilities、禁止提权、最多 128 个进程、384 MiB 内存、1 CPU。没有挂载用户目录、凭据、其他仓库或 Docker socket。

Go 缓存置于 128 MiB 临时 `/tmp`，显式设置 `rw,exec,nosuid,nodev`；禁用模块代理与自动工具链下载。运行 `go test -mod=readonly -count=1 -timeout 30s ./...`。

实际结果：

- 第一次未显式设置 tmpfs 的 `exec`，测试二进制在 `/tmp` 执行时报 `permission denied`，本次失败保留，不计为通过，总耗时 29.38 秒。
- 仅为一次性容器临时目录明确 `exec` 后重试，基线通过：测试报告 0.004 秒，命令总耗时 28.19 秒。源码挂载始终只读，容器结束自动移除，没有修改线上权限。
- 两次合计约 58 秒，均无模型调用。通过的是原始正常姓名测试，不是空名字等新需求验收，也不是生成代码安全测试。

注意：`go test -timeout` 限制测试运行阶段，并非整个编译和容器生命周期的截止时间。真实任务入口还必须实现外层总超时及指定容器清理，不能仅依赖这个参数。

## 5. 专用入口必须具备的保护

- 默认仅预检；显式授权后才能发送请求。保留唯一任务编号和基线 SHA，不能覆盖之前的证据或重置预算重试。
- 发送内容只从四个公开模板文件及任务描述构造，总源码快照不超过 128 KiB；排除 `.git`、环境文件、凭据和任何其他项目数据。拒绝符号链接、异常路径和未知文件。
- 模型调用进程与执行测试的容器分开：密钥不进入测试容器。补丁必须通过路径与大小检查、人工审批后，才能应用到独立工作副本。
- 把底层重试也计入用户确认的请求总数；请求前预留保守最高费用。超时或费用不明时保留预留并停止，不能当作免费请求继续调用。
- 执行前核对官方价格、模型、价格有效期和人民币预算的保守转换方案；没有可靠上限就不启动。文档中的建议额度不代表已经授权。
- 仅执行固定 Go 测试命令，使用无网络、非 root、限资源的隔离容器；限制整体耗时、输出大小，能停止且只清理本次任务容器。
- 保存真实补丁、测试退出码、输入版本、请求次数与实际用量；公开 PR 只放脱敏摘要。确认原始模板和线上仓库不变。
