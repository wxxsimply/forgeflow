## 前一轮：新增持久化预算组件（PR #58，已合并）

PR #57 已合并为 `bc1621e5bb24561c01523603cf7487a5e9b8e925`。本轮在该版本基础上新增 [预算组件](../scripts/preview_demo_budget.py) 和 [预算测试](../scripts/test_preview_demo_budget.py)，没有接入 DeepSeek 或新增付费 CLI，也没有创建正式任务账本。

通俗解释：先记账、再请求。模型请求的结果不确定时，不把它当成“没有花钱”，而是保留预留金额并停止，等人核对。不能靠重启程序自动恢复额度。

已实现：

- SQLite `BEGIN IMMEDIATE` 将调用次数和最高费用预留一起提交，成功后 `invoke_once` 才调用传入的单次请求函数。磁盘/提交失败时不调用该函数。
- 费用使用整数 nano-USD，`1 USD = 1,000,000,000` 单位，拒绝浮点数、NaN、负数和无效上限；它不是人民币。每个账本配置最多 1～3 次请求，已知费用为零的请求也占一次。
- 单次完成后将预留替换为实际费用；超时、缺失用量、结算失败保留预留。进程退出留下的 `reserved` 记录也阻止下一次请求，无自动退款或自动重试。
- 相同账本绑定源快照、任务、价格配置指纹及 Provider、模型、调用次数与费用上限；重启时配置变化拒绝打开。不存在的账本不会自动重建，创建不能覆盖旧文件，损坏数据库不会自动重置。
- 独立连接的并发预留通过事务串行化；一次只允许一个未结清请求，避免争用余额。遇到锁或数据库故障时阻断，不退回内存计数。
- 用量不明时仅提供显式 `reconcile` 接口：要求核对证据的 SHA-256，记录人工核对标记；不能重复结算或改低已结算费用。接口不会替人读取账单或做审批。
- 若报告的实际费用超过预估，保留真实费用并阻止后续请求；不能撤销已经发生的扣费，所以仍须在真实适配器中正确计算请求前最高费用。

没有完成、不能据此宣称的能力：

- `send_once` 当前只在测试中传入 Fake 函数；它必须不含内部重试。后续 HTTP 适配器要保证每一次实际请求都经过此边界，不能直接套用带自动重试的 SDK 后声称已经限次。
- 人民币预算转换、最新价格、token 上限和预留费用估算尚未接入。之前提出的“最多人民币 1 元”仍不是已授权、已实现的真实计费保证。
- 指纹只是配置一致性检查，不是用户授权签名；一个格式合法的证据哈希不代表已核实账单。授权界面、人工核对流程和真实回执真实性校验仍待实现。
- 本地 SQLite 不是防篡改账务系统。账本必须放在受控、已忽略的私有任务目录，Windows 还需合适的目录 ACL；禁止提交数据库及 journal、复制旧账本回滚额度或换路径创建新账本来续费。跨账本总预算和唯一任务目录绑定由后续入口负责。
- 补丁审批、修改独立副本和真实任务证据链仍未接通。线上网站继续使用 Mock，本轮未操作服务器或 Docker。

本轮离线验证：21 项预算测试加原 16 项预检测试，共 37 项全部通过，耗时约 1.30 秒。覆盖真实子进程突然退出后恢复、两连接并发、创建拒绝覆盖、配置漂移、事务提交失败、未知费用、显式核对、实际费用超估及错误脱敏。测试仅使用临时 SQLite 与 Fake，不产生模型费用。

运行快速检查：

```powershell

```

CI 已使用同一测试集合。账本只保存配置指纹、计数、金额、状态和证据指纹，不存任务正文、源码、API Key、原始响应或数据库连接串。该轮 PR #58 已合并，当前停止点见本文顶部。

## 前一轮实现：离线预检入口（PR #57）

PR #56 已合并为 `ba2231d8b3672897419ca518063c83692a444174`。在其基础上新增 [预检工具](../scripts/preview_demo_preflight.py) 与 [离线测试](../scripts/test_preview_demo_preflight.py)，仅完成独立执行入口的输入检查和基线沙箱部分，仍无付费执行功能。

默认运行只读取公开模板，返回文件名、大小和 SHA-256 指纹，不读取密钥、不启动 Docker、不发送网络请求：

```powershell
python -B scripts/preview_demo_preflight.py
```

只有显式指定 `--sandbox` 才会执行本地容器基线测试：

```powershell
python -B scripts/preview_demo_preflight.py --sandbox --timeout-seconds 90
```

要求本机已有受信任的 Go 镜像，默认 `golang:1.22-alpine`。工具先解析本地不可变 image ID，禁止自动拉取，不能使用未经审查的镜像。`--source` 只能指向你控制的、执行期间不被并发修改的平铺四文件模板目录；目录含 `.git` 或其他文件会被拒绝，所以不要指向完整 ForgeFlow 仓库或已初始化的线上 demo。

已实现的边界：

- 只接受 `README.md`、`go.mod`、`greeting.go`、`greeting_test.go`，总计不超过 128 KiB；拒绝未知文件、子目录、`..`、符号链接、Windows reparse point、硬链接、二进制和无效 UTF-8。
- 核对固定模块声明和 Go 版本，禁止添加依赖声明。检查读取前后的文件标识与时间，减少读取过程中内容变化的风险；这不是针对恶意并发文件系统写入者的完整隔离保证。
- 将捕获的字节复制到一次性目录后才挂载容器，源码只读；不挂载原仓库、Docker socket、凭据或宿主机缓存。
- 无网络、非 root、只读根、禁止提权、CPU/内存/进程数限制，只有用于 Go 测试的临时 `/tmp` 可写可执行。缓存及工具链下载关闭。
- Docker 日志驱动设为 `none`，不收集测试 stdout/stderr，避免不受限的原始输出；报告只包含退出码、OOM 状态和镜像 ID，失败细节需要另行受控诊断。
- 外层总截止时间覆盖镜像检查、容器创建、启动、编译与测试；默认 90 秒，最大 120 秒，另预留最多约 10 秒验证归属并清理。只操作本次随机名称且 owner label 匹配的容器，不批量删除。
- 创建超时也会尝试核对清理；若无法确认清理，返回 `cleanup_unconfirmed` 和本次容器名，不能算成功。不要自行运行全局容器或卷清理。

报告的 `checksPassed:true` 仅代表本次文件检查或原始基线测试通过。`readyForPaidExecution` 和 `paidExecutionEnabled` 始终为 `false`；指纹不是审批签名，文件白名单也不是密钥扫描器。

本轮检查：16 项离线单元测试通过（约 0.36 秒），已接入部署资产 CI；默认预检通过，当前模板为 1,081 字节。真实 Docker 基线通过，总耗时 35.39 秒，未 OOM，原始源码未改动。本轮没有测试新需求、没有费用、没有修改线上服务。后续实际源码换行或内容变化时，字节数和指纹可能不同，应重新核对，不能复用旧指纹。

另用 1 秒外层时限执行真实 Docker 负向检查，按预期返回 `checksPassed:false` / `docker_command_timeout`，无本工具标记的容器残留。这个结果是预期失败路径，不是业务测试失败；清理检查通过后才结束本轮。

## 4. 本轮免费隔离基线检查

本机 Docker Engine 可连接，版本为 `28.4.0`。使用已缓存的 `golang:1.22-alpine`，运行前解析本地不可变 image ID，`--pull never`，没有下载镜像。只将 `examples/preview-demo` 只读挂载至 `/workspace`。

Go 缓存置于 128 MiB 临时 `/tmp`，显式设置 `rw,exec,nosuid,nodev`；禁用模块代理与自动工具链下载。运行 `go test -mod=readonly -count=1 -timeout 30s ./...`。

实际结果：

- 第一次未显式设置 tmpfs 的 `exec`，测试二进制在 `/tmp` 执行时报 `permission denied`，本次失败保留，不计为通过，总耗时 29.38 秒。
