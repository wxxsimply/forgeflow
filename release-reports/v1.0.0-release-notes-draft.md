# ForgeFlow v1.0.0 Release Notes（草案）

> 在最终 GO 前不得发布。版本号、安装介质、兼容性、已知限制和证据链接必须从批准候选回填，不得使用 smoke 或计划值冒充实测结果。

## 概要

ForgeFlow 是使用 Go 构建的可治理多 Agent 软件交付平台，通过版本化 Prompt/model、确定性 Policy、人工审批、隔离 Git worktree、受限 Sandbox、独立 Reviewer/Security、真实测试 Evidence 和可审计 Judge 决策形成受控交付链路。

## 主要能力

- Planner → 计划审批 → Developer → Patch 审批 → Test → Reviewer/Security → Judge/Repair。
- PostgreSQL Checkpoint、事务 Outbox、Job lease/heartbeat/recovery 和独立 Worker。
- REST/SSE API、Session/CSRF/RBAC、React 控制台和审批 ETag。
- 默认拒绝的路径/命令/网络 Policy、固定 digest Sandbox 和资源/成本预算。
- OpenTelemetry、Prometheus、Eval、Prompt/model Promotion/rollback 和不可变发布清单。
- digest-only Staging、备份/隔离恢复、告警、安全与 Demo Runbook。

## 安装与升级

- 发布介质：待最终决定（Source Release / 签名容器镜像）。
- 支持平台：待由最终 manifest 回填；当前镜像计划为 `linux/amd64`。
- 首次安装：链接 `README.md`、`docs/operations.md` 和批准的 Production 私有 Runbook。
- 升级：先备份和 `db check`，仅执行向前 Migration，再按 digest 滚动发布。
- 回滚：应用和 Prompt/model 分别回滚；禁止自动 Down Migration。

## 安全与供应链

- Candidate Git SHA / manifest SHA-256：待回填。
- 五镜像 digest、SBOM、provenance、签名和漏洞结论：待回填。
- 独立安全评审和风险接受：待回填。
- 安全报告渠道：`SECURITY.md`。

## 已知限制

- 在对象存储适配器、专用 Production 执行面、管理员 MFA、外部不可变审计、数据 Region 和阶段 9 实测关闭前，不提供 Hosted Production 服务。
- 模型输出并非确定正确；任何 Patch 在合并或部署前仍需用户审核。
- Provider 可用性、价格和输出质量可能变化，费用/Token/时长受硬预算限制。
- 正式支持范围、SLO/RPO/RTO 和数据政策以最终批准记录为准。
